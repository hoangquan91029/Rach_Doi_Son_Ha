# Sprite timing and event metadata

Sections115–145 require whole illustrated frames, variable durations, generated atlas rectangles and event markers. `client/sprite-timing.js` samples elapsed milliseconds without a display-frame counter. Existing frame durations remain supported; nonlooping tracks hold their last pose. The art loader exposes current frame, local elapsed time, total duration and detached marker data. Markers are declarative only and never invoke commands or mutate simulation.

Optional frame metadata: `events: [{name: "LEFT_CONTACT", offsetMs: 0}]`. Names use uppercase letters/digits/underscores, starting with a letter, at most64characters. A frame holds at most32markers. Offsets are integer milliseconds within the declared frame duration. Both browser intake and Python packaging reject invalid markers. An omitted field means no markers.

Authoritative attacks now publish start, impact and recovery-ready ticks. Damage occurs after a validated fixed-tick windup; current movement, fog, target life and range are rechecked at impact. Browser presentation uses a bounded cosmetic clock and maps one authored contact marker onto the authoritative impact. Known shots trigger a deduplicated cosmetic pulse; events never deal damage. Actual illustrated attack tracks, projectiles, resource-transfer tracks and visual acceptance remain open. See `ACTION_TIMING.md` for implementation and the new 72-test/public acceptance receipts.
