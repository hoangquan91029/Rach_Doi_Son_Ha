## Assignment and lifecycle

Root records task ID, purpose, model, input path/SHA pins, exclusive files/directories/slots, actual tools, dependencies, forbidden operations, checks and stop condition. Tasks registry is an ownership index, not a second queue. One task/package receipt records outputs and failures. Code workers use disjoint files or isolated stages; only root integrates shared manifests, state, ledger and release.

1. Inspect Git/status/diff and live claims/locks/browser/server/test/preservation handles. Preserve uncommitted work.
2. Read subsystem contract, source and exact latest receipt. Declare observed tool availability; unknown stays UNKNOWN.
3. Run preflight with task/source and assigned snapshot. Hashing does not prove comprehension or permission.
4. Before a dependent mutation/call recheck affected input pins and ownership. Unrelated changes do not justify repeating checks. Drift stops affected work, not the whole project.
5. Perform only assignment. No new unit/action/direction, installation, image order or deployment beyond scope.
6. Retain initial errors and repair evidence. Use scoped tests; no fullmatch per sprite or fullsuite per docs edit.
7. Independent reviewer observes exact artifact and method. Producer cannot award own art PASS. Samples are SAMPLES_ONLY; unable to watch means UNKNOWN.
8. Root reviews outputs/diff and closes only known owned handles. Unknown provider completion remains unresolved; elapsed time never refunds a call.
9. Update state/queue and one receipt. Full goal OPEN until all critical gates in completion matrix close.

## Mechanical gates

Use existing preflight/finite runner and task-contract APIs; inspect their actual CLI/API before invoking. Future enforced orders bind taskId, scoped snapshot, method family/failed-parent evidence, selected prerequisites and durable-claim budget baseline. Historical orders stay historical; new safeguards are not retroactively claimed for old calls. A renamed closed method, reordered refs or prompt wording alone is not a different control mechanism. Root must assess new method semantics; a new family string cannot prove novelty.

Ownership compares physical paths (including symlink and parent-directory overlap) and slots. Workers do not edit shared registration files. Input snapshot covers exact dependencies; matching HEAD cannot hide dirty-byte drift. Output checks gate intake, not every possible shell operation.

Receipt records actual argv/cwd, outputs/log hashes, exit status, evidence class and observation/limit. Keep source/technical/motion/runtime/owner/release separate. Reject stills=continuous, old tests=rerun, localhost=public, owner rejection=approval, missing log=PASS. Structural checks do not authenticate arbitrary prose or human judgment.
