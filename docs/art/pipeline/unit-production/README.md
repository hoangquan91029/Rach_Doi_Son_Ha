# Identity and action authoring contracts

The shared `shared/unit-action-spec.js` defines nine ordinary identities plus twelve leaders and eight directions each. It requires idle4/walk8/attack8/hit4/death8 for combat identities; villager additionally wood8/food8/iron8/build8; wagon and transport replace attack with load8/unload8; each leader adds ability6 and King-role build8. Artillery/wagon destroyed and ship sink alias death. Villager repair aliases build and resource return aliases ordinary walk. No carry clip is required. Ability/load/unload require separately authored poses.

Each identity has `identity.json` with verified retained encoded source hashes, explicit missing views, scoped roles and custody limitations. Existing static views are not approved eight-direction animation. Missing leaders and warship retain null masters; no foreign portrait or role body is substituted. Infantry's sole master remains original084845…0517f. Wagon's master is whole original415 raw horse/cart/harness/cargo. Other derived source references retain their provenance and explicit pending original authority; they cannot serve as an originalmaster PRIMARY. Held/rejected infantry orders remain excluded. This registry makes no new selection judgments.

Five templates cover view, key, inbetween, correction and worker order. `renderPrompt` rejects missing, unexpected or unresolved fields, invalid direction and unavailable actions. `preparePrompt` requires every reference pin to match exact retained bytes and binds the primary master hash before returning a prompt for any future built-in image call. `validateMaster` is also available independently. Template rendering never calls an image service or grants approval. A future order must retain ordered references, actual tool response mapping, raw output, finite call budget and at most two visible corrections per action. No historical exhausted order is reopened.

Authoring sequence remains pilot first: qualify current infantry D0 keys/inbetweens with one normal-size loop and actual travel/Stop before view fanout. Other identities remain blocked on identity/view locks and runtime action mappings where absent. Compiler471 consumes whole-frame jobs after authored output exists. Source, review, runtime and release are separate gates.

Pre-call references now bind to the on-disk identity registry. PRIMARY must be the exact originalmaster or an explicitly selected matching directional view. Existing static views are not silently selected. Secondary neighbors must be registered selected sources, with exact frame/phase/current-job binding and a pinned compiler job. Optional guides require a registered original-master derivation and pinned provenance. Unregistered, foreign and held references fail even when their file SHA is valid. Physical weapon ownership must have a verified lock; other identities currently retain an explicit missing lock and cannot pass preparation until reviewed. Screen-facing labels derive from the existing eight world octants projected through the fixed 2:1 ground basis; camera language preserves the original elevated whole-frame composition without equating ambiguous historical elevation metadata.

The expanded templates require camera, screen-facing, physical weapon ownership and explicit reference roles. Key/inbetween/correction/order templates additionally require concrete moving parts, body movement, equipment movement and next-key intent. Plain `renderPrompt` remains a strict text renderer; only `preparePrompt` validates production reference authority.
