# M0 coverage inventory

Run `node scripts/unit-art-coverage.mjs` from the project root to regenerate the JSON and Markdown. The optional argument is a read-only PUBLIC451 fort manifest; its SHA must equal the preserved public451 SHA. Default input is the retained `dist/assets/art-v1/fort-202-manifest.json`, verified by hash. This is a local retained release snapshot comparison, not a live URL or backend qualification.

The registry is imported from `shared/unit-art.js`; action requirements come from `shared/unit-action-spec.js`: nine ordinary identities and twelve named leaders, all eight directions. The twelve-action union has 2016 rows, including N/A slots; 1080 applicable slots require 7104 authored frames. Leaders share one identity artwork across King/general roles, with build restricted to King. Villager repair aliases build and resource returns alias ordinary walk; artillery/wagon destroyed and ship sink alias death. Ability/load/unload require separate poses; no carry clip is required.

The exact coverage enum is `exact animation`, `shared clip`, `static fallback`, `missing`, `not applicable`. The first records actual multi-frame source presence, not visual approval or fulfillment of required frame count. Static exact assets and living idle substitutions are static fallback. Aliases can report shared canonical clips without duplicating authored frames. Source presence, review receipts, runtime receipts and release bytes remain orthogonal. Neither static D0 nor fallback completes any eight-direction animation target.

Only the active fort manifest contributes source coverage. Portraits, opt-in food099, historical authored death321, held infantry keys443/465 and rejected identities do not count. One frame with `loop:true` remains static. A same-identity matching-direction idle, then D0 idle, can be listed for missing living actions, but cannot fill exact action or animation coverage. Death and construction never receive living fallback. Unknown leader identities cannot borrow role or foreign leader art.

`evidence.json` is a deliberately explicit scoped receipt mapping. Each receipt is pinned by file SHA, and each mapped asset by runtime SHA; regeneration rejects changed or missing receipt bytes and stale asset bindings. Tests verify these bindings without granting review. Wood032 and iron141 accept only shown D1 naturalness, not world contact, direction fanout or final release. Walk016 supports historical local runtime observation only. Static intake receipts establish source custody only. Current manifest candidate flags are retained; no test result upgrades review. Unmapped rows are unreviewed or unverified. Source presence, multi-frame format, scoped motion, scoped runtime and public byte presence remain independent fields.

Decoded RGBA estimates deduplicate runtime path plus SHA across all manifest assets (including terrain/structures). This matches atlas sharing without multiplying by action, direction or alias; it is neither browser memory measurement nor a performance claim. Different SHA bytes at the same path count separately. Conflicting dimensions on one path plus SHA fail rather than silently undercounting.

Focused validation: `node --test tests/unit-art-coverage472.test.js`. No game build, image call, deployment or production mutation is required.
