**High-quality 2D illustrations + convincing three-dimensional depth + frame-by-frame sprite animation + an angled RTS camera.**

Think of classic illustrated and pre-rendered RTS sprites, but do not assume that their original 3D production techniques are necessary.

The final appearance matters more than replicating their production methods.

Every animation frame must be an actual 2D image.

## 2. THE EXACT VISUAL STYLE I WANT

The characters should have the appearance of high-quality, realistic or semi-realistic historical illustrations.

A 2D image should convey the impression of a volumetric human body through:

- Realistic lighting and shading
- Anatomically believable proportions
- Natural skin shading
- Cloth folds and wrinkles
- Occlusion between body parts
- Detailed material textures
- Realistic depth
- Correct perspective
- Ambient shadows
- Soft contact shadows
- Consistent highlights
- Convincing silhouette

The result must NOT look like:

- Flat cartoon stickers
- Vector characters
- Low-detail icons
- Pixel-art placeholders
- Simple geometric shapes
- Paper dolls assembled from detached limbs
- Cutout puppets with visible seams
- 3D low-poly models
- Untextured geometry
- Cheap procedural characters

**The image must look dimensional, but it must remain entirely 2D artwork.**

This is an art-direction requirement, not a requirement to use a 3D engine.

## 4. PURE 2D FRAME-BY-FRAME ANIMATION

The final animation system must use sequences of finished 2D image frames.

Example:

`villager_walk_s_000.png`

`villager_walk_s_001.png`

`villager_walk_s_002.png`

`villager_walk_s_003.png`

`villager_walk_s_004.png`

`villager_walk_s_005.png`

`villager_walk_s_006.png`

`villager_walk_s_007.png`

When the frames are played sequentially, they create motion.

This is similar to traditional cel animation or flipbook animation.

The runtime must not require:

- 3D skeletons
- 3D character meshes
- 3D animation clips
- 3D character rendering
- Runtime puppet-style body assembly

The runtime should simply display the correct finished sprite frame according to animation state and facing direction.

## 7. SOLVE THE SUPPORTING-LEG PROBLEM

The current major technical problem is that independently generated walking poses repeatedly fail to switch supporting legs correctly.

Fix this using explicit 2D key-pose planning.

Start with an eight-frame walking cycle:

| Frame | Main pose |
|---|---|
| F0 | Left foot forward contact |
| F1 | Weight transfers onto left leg |
| F2 | Right leg passes the supporting left leg |
| F3 | Left leg pushes off |
| F4 | Right foot forward contact |
| F5 | Weight transfers onto right leg |
| F6 | Left leg passes the supporting right leg |
| F7 | Right leg pushes off |

The sequence must form a continuous loop.

Do not assume that all phases have an exclusively planted foot; brief transitions between contact and push-off must remain anatomically plausible.

Validate:

- Left/right identity
- Foot contact
- Support-leg alternation
- Stride length
- Weight transfer
- Leg crossing
- Body bounce
- Arm counter-swing
- Clothing movement
- Root consistency
- Loop continuity

Generate key poses first.

Only create in-between frames after the key poses pass validation.

Do not generate all eight images independently from unrelated text prompts.

## 8. HOW TO PRODUCE THE FINISHED 2D FRAMES

Use a controlled illustration workflow.

### Phase A — Canonical Artwork

Preserve one approved character design.

This establishes:

- Face
- Body proportions
- Clothing
- Color
- Equipment
- Material style
- Light direction
- Camera perspective

### Phase B — Key Poses

Create the essential key poses from the canonical character.

Use reference images, masks, pose guides, and 2D editing to control the motion.

### Phase C — Anatomy Validation

Confirm that the key poses show correct movement before spending time refining details.

### Phase D — Finished Frame Illustration

Render or paint the frame as one coherent 2D illustration.

Correct:

- Clothing folds
- Shoulder contours
- Hip deformation
- Arm overlap
- Leg overlap
- Hat position
- Lighting
- Shadows
- Material continuity

### Phase E — In-Between Frames

Create additional poses between validated keyframes using controlled 2D image generation/editing.

Use neighboring frames as references.

Do not regenerate the character identity.

### Phase F — Quality Control

Inspect the full animation as a contact sheet and animated preview.

Reject:

- Limb swaps
- Identity drift
- Clothing drift
- Inconsistent anatomy
- Changing proportions
- Broken feet
- Unnatural motion
- Flickering textures
- Floating objects
- Missing details

### Phase G — Export

Export the approved complete character images as transparent PNGs.

Preserve their pivot metadata.

Pack the finished frames into web-optimized sprite atlases.

## 9. DO NOT SIMPLY ROTATE LIMB IMAGES

This is extremely important.

A common failure of 2D puppet animation is rotating separate images of:

- Arms
- Forearms
- Thighs
- Lower legs
- Torso

without correctly reconstructing clothing and anatomical transitions.

That creates visible puppet seams.

For this project:

**Rotated 2D components are allowed as pose guides, but the final frame must be visually reconstructed into a complete illustration.**

For example:

When the leg moves forward, the tunic should naturally overlap the thigh.

When the arm rises, the shoulder and sleeve should deform naturally.

When walking, the sash and loose clothing should follow the motion.

Do not leave gaps between the limbs and torso.

Do not accept disconnected clothing shapes.
