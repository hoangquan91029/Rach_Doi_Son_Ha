# Authoritative presentation episodes 478

Source implementation only; no production/runtime deployment or art animation acceptance.

Private `actionEpisode` stores one bounded cosmetic action kind plus start/end/last ticks. `view` omits that private object and exposes only current `visibleAction: {kind, startedTick, endTick, loop}` for ability/load/unload/build. No target, passenger, cargo quantity or future order is added to that action payload. Existing gather resource and loaded-villager walk behavior remains intact.

Successful ability activation starts a 12-tick cosmetic interval. Wagon transfer starts only after actual positive food flow and renews its one-tick end bound while work continues, retaining the episode start through contiguous ticks. Actual transport boarding or successful passenger placement starts a finite 12-tick interval. Full/empty/rejected transfer requests do not start poses. Positive construction/repair work renews a build episode; repair requests the same authored build state.

Interrupt policy: accepted replacement orders (from the validated move/attackMove/stop/hold/attack/repair/gather/build/load/unload branches only, including stop, move and attack) cancel stale episodes. Actual movement cancels them; public selection gives movement priority. Hit/death and pending/current attacks preempt the pose; damage and automatic attack cancel episodes. Episode time derives solely from sanitized authoritative ticks and remains bounded at its end; presentation clocks retain existing pause handling. No order, movement speed, resource transfer, cooldown, damage, simulation time or result is changed.

Raster selection requests the active exact authored action first. Missing art retains the existing same-family idle fallback and records the requested action separately from the static illustration; no authored action is claimed from that fallback. Continuous wagon transfer and build/repair episodes explicitly expose `loop: true`; finite transport transfer and ability episodes expose `loop: false`. The raster sampler uses this authoritative cosmetic policy for these active episodes. Finite episodes normalize their bounded elapsed time to the selected authored clip duration, so a 600 ms episode can present an 800 ms clip over that interval without altering simulation. Continuous work retains its start clock and repeats the selected clip. Asset loops remain explicit metadata, but the work episode determines continuous versus finite playback. Actual artwork is still missing and this timing contract has no rendered motion qualification.

Validation: `node --test tests/action-episodes478.test.js tests/action-presentation.test.js tests/visible-action.test.js tests/gather-episode.test.js` passed 18/18. The new contracts cover successful/no-op/full transfer cases, finite boarding/unload, construction/repair, stale-order interrupts, movement/hit/death priority, bounded timing and private payloads. Frozen prechange simulation bytes are retained under `before/`; four representative ability/load/repair/move scenarios run 18 ticks each and compare complete gameplay state after stripping only the new private `actionEpisode` field. This is a finite fixture check, not a full-match, performance, browser or art qualification.
